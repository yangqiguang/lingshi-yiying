============================================================
 灵视医影 · 个人康复 APP —— HBuilderX 打包说明
============================================================

一、这是什么
------------------------------------------------------------
本工程是一个 HBuilderX / uni-app（Vue3）项目，内部用全屏 web-view
承载高保真 H5（共 26 屏，底部 4 个 Tab，含 AI 康复助手、医护工作台
与关于灵视医影）。页面、图表（自绘 SVG）、前后对比滑块 100% 原样保留，
无需重写即可用 HBuilderX 打包成安卓 APK（也支持 iOS）。

二、目录结构
------------------------------------------------------------
灵视医影/
├─ pages/index/index.vue   启动页：全屏 web-view，指向本地 H5
├─ pages.json              页面配置（自定义导航、沉浸式、深色打底）
├─ manifest.json           应用配置（名称、图标、状态栏、权限）
├─ main.js / App.vue       uni-app 入口（脚手架默认，未改动）
├─ sync-h5-to-app.bat      ★一键把 h5/ 同步到 hybrid/html/（双击运行）
├─ static/
│  ├─ icons/android/       应用图标 48/72/96/144/192
│  └─ app-icon-1024.png    1024 主图标（iOS 或手动生成用）
├─ hybrid/html/            ★被打包进 APP 的 H5（App 端专用）
│  ├─ index.html
│  ├─ app.css / app.js
│  ├─ config.js            ★运行期配置（AI 后端地址、演示日期）
│  ├─ app-bridge.js        原生壳桥接（状态栏/返回键/安全区），仅此目录有
│  └─ assets/              logo、两张腕部 X 光（WebP，共约 68 KB）
└─ h5/                     H5 源文件（桌面演示、后续改页面用它）

说明：h5/ 是“源”，hybrid/html/ 是“打包进 APP 的副本”，
      两边内容一致，仅副本多一个 app-bridge.js。
      日常改页面只改 h5/，改完双击 sync-h5-to-app.bat 即可，
      不要再手工复制（手工复制容易漏文件，导致两版不一致）。

三、用 HBuilderX 打开并打包（安卓 APK）
------------------------------------------------------------
1. 打开 HBuilderX（建议 3.99 及以上正式版）。
2. 菜单：文件 → 导入 → 从本地目录导入，选择本文件夹
   （...\app\灵视医影），注意选到含 manifest.json 的这一层。
3. 双击打开 manifest.json：
   - 「基础配置」里点“重新获取 DCloud AppID”（需先登录 DCloud 账号），
     获取后保存。没有 AppID 无法云打包。
   - 应用名称已填“灵视医影”，版本 1.0.8。
4. 真机预览（推荐先验证）：
   - 手机开启“开发者选项 → USB 调试”，数据线连电脑；
   - 菜单：运行 → 运行到手机或模拟器 → 运行到 Android App 基座；
   - 首次会在手机装“HBuilder 标准基座”，随后自动打开本应用。
5. 云打包成 APK：
   - 菜单：发行 → 原生 App-云打包；
   - 平台勾选 Android；证书可选“使用 DCloud 公共测试证书”
     （比赛演示足够；正式上架再用自有证书）；
   - 点打包，等待几分钟，完成后给出 APK 下载链接，装到手机即可。

六、AI 康复助手怎么连真模型（已配好，只需部署后端）
------------------------------------------------------------
★ 结论先说：App 装在本机、页面不上云，AI 一样能真联网。

原理（一句话）：App 里的 web-view 页面跑在 5+ 运行时里，能拿到
plus.net.XMLHttpRequest —— 这是原生网络栈，不是浏览器发的请求，**不受
同源策略约束**。所以 file:// 页面可以直接请求 http://<后端地址>。

   通道优先级（app.js 里 apiTransport()）：
   ① plus.net.XMLHttpRequest   App 内，无同源限制  ← 真机走这条
   ② fetch                     浏览器 / H5 调试（后端已配 CORS）
   ③ 本地模板                   两条都不通时兜底，页面顶部如实标注

1) 地址已填好：h5/config.js
     AI_API_URL: 'http://127.0.0.1:5000'
   本地调试可改成 'http://127.0.0.1:5000'。
   留空 '' = 不联网，走本地演示数据，断网也能完整演示。

2) 明文已开：manifest.json 里
     app-plus → distribute → android → "usesCleartextTraffic": true
   安卓 9+ 默认禁止 http 明文。不开这一项，打包后所有 http 请求会被系统
   直接掐断，现象是「连不上」且没有任何报错，很难查。这一项已经加好了。

3) 服务器端（你自己的云主机）要做的三件事
   a. 上传（只传 ai-server/ 里的这几个文件，app/ 整个目录不要传）：
        ai-server/app.py             ← 新版后端（五角色工作台 + 真实推理）
        ai-server/detector.py        ← ONNX 推理接入层
        ai-server/models/best.onnx   ← YOLO26n 模型（9.4MB）
        ai-server/requirements.txt
        ai-server/deploy-2g.sh       ← 2G 内存一键部署脚本
   b. 一键部署（在服务器上执行，会自动建 swap、装依赖、写 systemd、启动自检）：
        cd /opt/ai-server && sudo bash deploy-2g.sh
      脚本中途会提示粘贴百炼 Key（可回车跳过、之后补）。
      自检：服务器上执行 curl http://127.0.0.1:5000/api/model/status
        看到 "available": true 就说明模型就位了。
   c. 阿里云控制台 → 安全组 → 放行入方向 TCP 5000

4) 前端 AI 提问会把「当前病例号」带给后端，后端注入该病例的真实字段
   （检查、模型结论、技师报告、医师意见、康复方案、随访）作为上下文，
   模型回答与档案完全一致，不会编造检查值或日期。

5) 打包装机后怎么验证通没通（30 秒，不用看代码）
   打开 App → 登录 → AI 康复助手 → 提问，看页面顶部那行字：
     「已连接 AI 服务」               → 通了，真模型在回答
     「已连接 AI 服务（知识库模式）」 → 通到后端了，但后端没读到模型密钥
     「AI 服务暂时不可达」            → 没通
   影像识别：报告页 → 影像查看 → 点「AI 识别」按钮，
     识别结果会把骨折框叠加在原图上，显示「疑似骨折 · 87%」这类结果；
     显示「未部署模型」说明服务器上没有 models/best.onnx。
   没通时的排查顺序：
     ① 手机浏览器直接访问 http://127.0.0.1:5000/api/model/status
        能出 JSON → 网络和端口没问题，问题在 App/打包侧；
        出不来   → 安全组没放行，或服务没起。
     ② 确认 APK 是「重新云打包」的，旧包没有 usesCleartextTraffic。
     ③ 确认 h5/ 改完已同步到 hybrid/html/（双击 sync-h5-to-app.bat）。

6) 万一真机上第 5 步显示「暂时不可达」（即 plus 通道不可用）
   兜底方案（改动很小，但页面就变成从服务器加载）：
     - 把 h5/ 整个目录上传到服务器，例如 http://<后端地址>/app/
     - pages/index/index.vue 的 web-view src 改成该地址
     - config.js 里 AI_API_URL 改成 '/api'（同源，走 fetch 即可）
   这条路顺带的好处：评委能直接用浏览器在线体验，不用装 APK；
   改文案也不用重新打包。代价：断网时是白屏。


七、内容与数据的两个约定
------------------------------------------------------------
1. 病例日期不是写死的：打开时以“运行当天”为基准相对推算
   （受伤 = 今天-15 天、上次复查 = 今天-1 天、下次复查 = 今天+9 天、第 3 周），
   所以 11.6 网评、路演、答辩任何哪天打开，都不会出现“复查日期已经过去
   但还写着还有 20 天”的情况。
   想固定在某个日期演示，把 config.js 的 DEMO_DATE 填成 '2026-11-06' 即可。
2. 训练打卡进度：联网模式（SYNC_ENABLED: true）下写服务器 SQLite、跨设备同步，
   患者打卡后医师工作台能看到最新进度；关闭联网（SYNC_ENABLED: false）则写本机
   localStorage、断网也能演示但不同步。

七·补、联网数据同步开关（config.js 新增）
------------------------------------------------------------
config.js 现在有四个关键配置：

  AI_API_URL     后端地址，默认 http://127.0.0.1:5000
  SYNC_ENABLED   true = 登录/注册/病例/AI/影像识别/医护工作台都真联网（走服务器）
                 false = 全部回落到本机 localStorage 演示（断网可用）
  DETECT_CONF    影像识别置信度阈值，默认 0.15，低于不显示框
  AI_API_TIMEOUT 请求超时毫秒

联网模式下的数据流（与网页工作台共用同一套后端与数据库）：
  · 患者/医护注册 → 提交服务器，管理员在「账号管理」云端审核通过后登录
  · 患者登录 → 从服务器拉取本人病例（真实病例号回填首页 + AI 上下文）
  · AI 对话 → 带 case_no 调 /api/ai/chat，后端注入真实病例字段
  · 影像识别 → 调 /api/ai/detect，YOLO26n 推理返回归一化骨折框叠加到原图
  · 医护工作台 → 从 /api/summary + /api/cases 拉真实 KPI 与待审核队列
  · 管理员 → /api/admin/users + /api/admin/pending 真实账号与注册审核

八、说明与限制
------------------------------------------------------------
- 当前为高保真原型 + web-view 套壳；联网模式（SYNC_ENABLED: true）下账号、
  注册审核、病例、随访都存服务器 SQLite，与网页工作台跨设备真联动；
  关闭联网则回落到本机 localStorage 演示数据。
- 演示账号（服务端已 seed，密码均为 123456，登录账号即手机号）：
    患者       13700000001 / 123456
    执业医师   13800000001 / 123456    （登录页先切到「我是医护」）
    影像技师   13800000002 / 123456
    康复治疗师 13800000003 / 123456
    机构管理员 13800000004 / 123456
  也可点“仅浏览模式 · 不登录”直接看患者端。
- 影像识别用的是你训练的 YOLO26n（models/best.onnx，fracture/normal 两类），
  在服务器端 onnxruntime 推理；识别结果为「疑似提示」，非确诊，答辩时按此口径表述。
- 本环境无法替你完成云打包（需 HBuilderX 登录 DCloud 账号），
  按第三节操作即可；如后续要“真原生页面”或上架，可再将页面迁移为
  uni-app 原生组件。
- iOS 打包：manifest 图标界面用 static/app-icon-1024.png 自动生成全套
  iOS 图标即可；其余流程与安卓类似（需 Apple 开发者账号才能装真机）。
